Pulse Anatomy

How a cohort file, a request and the engine's internal machinery combine to produce one result. The plates follow a single request from bytes on disk to the JSON envelope, then step back to show how the whole instance describes itself to the tools that drive it.

PlateI

The .pulse file carries its own schema

A cohort is one binary file: a 9-byte header, the schema, inline dictionaries, then fixed-width records. Every reader can tell what the bytes mean without any outside description.

Version is earned

Byte 8 is 0x01 unless the schema declares a parent group, which makes it 0x02. Every ReadSchema call is handed the version that ReadHeader returned.

Type sets the width

Each field's type decides its width, and the widths together set the row's stride. date counts epoch days and datetime counts epoch seconds. Mixing them up rescales every value by 86,400.

Null is its own bit

The trailing bitmap exists only when some field is nullable. An empty set_* mask means "nothing selected", which is a different thing from null.

PlateII

What each call reads, and where execution starts

Most of Pulse's surface answers questions without decoding a single record. Only a lookup or a run crosses the line into row data, and a run decodes only the columns the request names.

Predict never runs

internal/descriptor/predict.go may not import the service or processing packages. A CI gate enforces this, so a predict can never touch a record.

Counting is arithmetic

Record count is payload length divided by stride. Inspect warns about a truncated tail; CountRecords deliberately floors without a warning.

Projection is free

NeededFields walks every slot of the request, including formula identifiers, and the decoder skips every other column. The output is byte-identical; disable it with --no-project.

PlateIII

A request's journey through the service

The stages Service.Process runs, in the order the code runs them. Almost everything that can refuse a request runs before the first record is decoded, so a bad request fails fast and cheaply.

Defaults need the file

A slot that names a field but no Type gets its operator from the schema type, so smart defaults run only after the header and schema are open.

Refuse before reading

Field references, weights, limits and labels are all checked against the schema alone. A request that will fail never pays for a decode.

One fold, every arm

Multiplicity correction runs once after dispatch returns, so the serial, streaming, fused, sharded and parallel arms all get corrected in the same place.

PlateIV

Inside the processor: two ways to walk the rows

The buffered arm loads every record and sweeps the whole set stage by stage. The streaming arm keeps only running state and pushes each record through all stages before reading the next. Both arms produce the same result.

Features see everything

On both arms, feature engineering runs before any filter. Streaming pays for that with a first pass and an iterator reset.

Order is semantics

On both arms the filter decides first, row-local attributes land next, and only then do floors and null tallies read the row. An attribute label used as a field is always read after it has been written.

ProcessStream is a view

ProcessStream is not a separate engine. It runs Process, wraps the rows in an iterator, and applies the return plan to each row. Streaming is a choice the engine makes internally.

PlateV

Choosing an execution arm

The same request can run on any of five arms. Each check below picks one, and every arm returns the same bytes. What decides it is mostly one property of the request: whether its operator state can be merged.

Merge order is fixed

Partials fold in shard or worker order, never in the order they finish. That keeps Welford variance results within one ULP of the serial run on every run.

Fusion is mostly memory

The fused crosstab skips materializing records and the recursive partition. Peak heap falls 8.8× to 20.8× in the fan-out benchmarks.

Extensions declare, not detect

An embedder operator streams or merges only if its registration declares it. A probe at pulse.New refuses a declaration the code cannot honour.

PlateVI

Crosstab: who counts where

Margins are recomputed from raw rows instead of summed from cells, so a record with only one axis resolved still counts in that axis's margin. Auxiliary margin figures follow a stricter admission rule.

Per-axis nullity

A record with a row key but a null column key updates the row margin and the grand margin. Cells exist only where both axes resolve.

Auxiliary margins

margin_aggregations excludes three kinds of record: those with a null cell field, those with an unresolved row key, and those with an unresolved column key. The cell aggregator's own margins are unaffected.

Both arms agree

The fused arm folds each record into its cell and margin accumulators as it decodes. It is byte-for-byte equal to the buffered RunCrosstab, overlays included.

PlateVII

Anatomy of the answer

Every slot of the response traces back to a stage of the run. Derived layers sit next to the base result and never overwrite it. Overlays are read-only siblings, and multiplicity adds an adjusted p beside the raw one.

Components show the evidence

Every aggregate has a floor of {n, n_null}. Filterers report {n_in, n_out, n_null_input}. Each figure carries the counts it was computed from.

Undefined is null

A NaN or Inf figure is sent as JSON null and its key stays in place. Reading the result back decodes that null to NaN, never to 0.

Absent means excluded

A part excluded by return is missing from the output entirely rather than null. When an excluded part was never computed, the run saved that work.

PlateVIII

The self-describing instance

pulse.New merges built-ins, extensions and an optional feature profile into one instance. That instance describes exactly what it supports, and an agent can learn to use it from the manifest and skills alone.

Read once per session

The manifest is deterministic and sort-stable, so a client can cache it. The manifest is the authority on what is registered; a tool count is never hardcoded anywhere else.

The filesystem is the index

Skills are embedded with //go:embed *.md and named by surface. There is no index file, and CI fails if any operator, tool or type lacks its skill.

Profiles shrink everything

A profiled instance mounts only what it enables. Its manifest, schema, error list and MCP tools omit every hidden feature.
